⚙︎ Mock Device Admin

A pretend router UI whose fields are locked client-side, for testing the agent's unlock → verify → patch loop. Watch the npm run mock terminal to see what each Save actually sent.

LAN — address range tier-locked

The start address is greyed out in this firmware tier. It's a plain disabled field: a disabled control isn't included in the form the page submits, so just unlocking it is enough — the value then rides along.

Try: Change the LAN IP range start to 10.0.0.1 — it's greyed out, unlock it and save.

DHCP — address pool tier-locked

The pool end is locked, and this page is sneakier: even after you unlock and type, its Save handler builds the request from a fixed field list that omits the pool end. The value never reaches the device until it's injected into the outgoing request.

Try: Set the DHCP pool end to 192.168.1.250 and make sure it actually saves.

WAN — MTU tier-locked

MTU is locked at 1500. Here the page sends whatever you set faithfully — but the device itself refuses anything above 1500. This is the case the agent should be able to prove is real, not just a UI trick.

Try: Set the WAN MTU to 9000 and save it. (the device should reject it)
